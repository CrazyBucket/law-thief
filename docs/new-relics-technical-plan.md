# 十件新遗物·临时技术方案

> 状态：技术方案与实施记录，不包含实现代码。  
> 范围：新遗物设计第 1、2 组，共 10 件。  
> 当前进度：已实现 1【创可贴】、3【赝品】、4【保险丝】、5【调包】、6【护膝】、7【退场哨】、8【拾荒钩】、9【斗兽票】、10【飞轮】；2【探针】跳过。

## 已确认口径

- 十件遗物全部唯一，不可重复获得。所有定义使用 `unique: true`，沿用现有 `RunState.add_relic()` 的去重行为，不新增遗物层数或叠加模型。
- 数值进入 `relic_numeric_refs.json`，遗物定义只引用数值键，避免把平衡数值写死在规则代码中。
- 简单事件效果继续由 `RelicEffectRegistry` 分发；改变槽位、宝石位置、AI 目标或攻击结算的效果进入独立规则模块，不在注册表中堆叠特例。
- 新增一个可被 `GameState.clone()` 完整复制的战斗内遗物状态，保存每回合使用次数、钩挂宝石、报复目标和飞轮层数。纯 UI 选择态仍留在战斗场景，不写入战斗规则状态。
- 所有宝石移动继续经过统一转移边界；所有伤害、移动和状态变化继续经过现有事务与事件结构。
- 新增玩家可见文本进入本地化数据。新图标使用 PNG/WebP；功能验证阶段可暂用现有遗物占位图。

## 共用基础改造

### 1. 遗物事件补充

在现有事件之外补四个明确事件：

- `voluntary_move_finished`：一次玩家机动最终结束，携带起点、终点与实际移动消耗。
- `after_gem_operation`：玩家拔出或嵌入完成且敌人意图刷新后触发，携带操作前后意图是否发生实质变化。
- `after_damage_taken`：实际生命伤害结算后触发，携带受害者、伤害来源、伤害量、原因和伤害上下文。
- `enemy_action_finished`：一名敌人的完整行动窗口结束后触发；额外攻击全部完成后只触发一次。

这些事件只描述已经完成的事实，遗物不在伤害或宝石事务执行到一半时重入结算。

### 2. 战斗内遗物状态

新增 `RelicBattleState`，由 `GameState` 持有并参与克隆，主要字段为：

- 每回合/每场已使用标记；
- 赝品占位记录；
- 拾荒钩的宝石、原掉落位置和到期回合；
- 斗兽票的受害者与报复来源；
- 飞轮层数；
- 调包本回合是否已使用。

不使用 `RunState.relic_runtime` 保存这些状态，避免战斗内状态跨战斗残留。

### 3. 移动力记账

当前移动力是“本次机动预算”，移动后不会直接扣减面板值。为了支持【护膝】和【飞轮】，增加本回合移动预算与实际消耗记录：

- 玩家回合开始时记录可用移动预算；
- 每段自愿移动按路径成本累计消耗；
- 临时移动力增加预算，移动力降低同步收缩预算；
- 回合结束时以 `max(0, 预算 - 已消耗)` 得到未消耗移动力。

该记录只负责统计，不改变现有“一回合一次机动”和【游标卡尺】分段移动规则。

## 逐件方案

### 1.【创可贴】— 简单

- 入口：沿用 `after_extract`，以 `from_uid` 作为被拔出宝石的单位，而不是执行拔取的玩家。
- 结算：宝石成功离槽后，对来源单位调用现有护盾规则，赋予 2 点护盾；地面拔取不发送该事件。
- 注意：护盾仍遵守现有“保留较高值、不相加”的状态规则。
- 验证：玩家自拔、敌人被拔、地面拔取、锁定槽失败四种场景。

### 2.【探针】— 设计待定

当前设计稿仍标记为“机制近似，待重做”，因此不能把它当作已定稿遗物直接实现。

若确认沿用当前版本，技术入口如下：

- 在攻击管线命中目标已经确定后，按该目标的空槽数计算普通射击直伤加成。
- 加成只进入直接命中伤害，不写入攻击基础伤害，避免同步放大爆炸、电弧、碰撞和状态伤害。
- 攻击空地、射线擦过其他目标或非玩家攻击不触发。

在正式实施第 2 件前，需要先确认是沿用该版本，还是提供替代设计。

### 3.【赝品】— 复杂

- 拔出前后仍由普通宝石转移处理，真实宝石正常进入玩家手中。
- 每个玩家回合第一次从敌人拔取时，在原槽生成特殊宝石【赝品】并锁定该槽一回合。赝品没有任何能力配置，不提供标签或槽位效果。
- 敌人失律检查暂时把该槽视为仍有宝石，因此不会立即失律；赝品锁保证其不能再次拔出、嵌入、调包或参与过载。
- 敌人的完整行动窗口结束后移除赝品、解除槽锁，再调用一次正常的离槽后行为，使失律在该时点发生。
- 若敌人在行动前死亡，赝品会在掉落与宝石死亡效果之前直接移除，不掉落、不触发黑槽或其他死亡效果。
- 宝石定义明确禁止加入随机池；普通敌人生成、奖励、商店和随机变换都无法选到赝品。
- 与【拔取残响】争用同一原槽时，赝品先占槽且本次不生成残响；拔取残响副本本身不会生成赝品或消耗赝品次数。
- UI 沿用现有宝石图标与槽锁显示：灰色【赝品】宝石加锁定状态，不伪造原宝石名称或效果。
- 验证重点：额外攻击只清除一次、行动前死亡、同回合第二次拔取、分裂锁/BOSS 锁、意图延迟刷新。

### 4.【保险丝】— 复杂

> 实现状态：已完成。

- 第一次正式生成过载槽时，给该槽记录 `deferred_mutation`，表示它占用一个异变席位但本场不产生异变。
- 过载同步数量改为：`真实异变数 = 有效过载宝石数 - 延迟异变槽数`。这样不会为了补足数量而在本场额外生成异变。
- 战斗胜利结算时，清除该槽的延迟标记，再通过正常的确定性异变抽取补出一条真实异变，从下一场开始生效。
- 若对应过载槽在战斗结束前消失，延迟标记随槽消失，既不生成异变，也不影响其他过载槽的异变。
- 已存在异变不暂停；后续过载仍立即生成异变；每场只保护第一次。
- HUD 的过载详情区分已生效异变与已熔断席位，遗物角标显示本场可用、待结算或已熔断状态。
- 手动可视化探针 `fuse_relic_visual_test` 在图形环境输出一张包含遗物角标与过载详情的战斗 HUD 截图；无图形验证环境检查同一 HUD 状态投影。
- 验证重点：预兆取消不消耗、首次正式过载、同场第二次过载、对应槽被拔除、胜利后的存档恢复。

### 5.【调包】— 复杂，含专属 UI

> 实现状态：已完成。

- 新增独立的遗物主动模式，不复用普通拔出/嵌入指令。
- 规则层提供原子交换：先一次性校验两个不同槽位均有真实宝石且可操作，再交换两个 `gem_uid` 并同步宝石归属；任一校验失败则完全不修改状态。
- 交换不触发拔出、嵌入、失律、赝品、过载或相关遗物事件；完成后只统一刷新一次敌人意图。
- 调包作为一次完成的非嵌入行动，会取消此前尚未结算的连续嵌入过载预兆。
- UI 流程：点击遗物按钮进入调包模式 → 点击单位打开槽位面板 → 点击第一颗宝石 → 点击另一单位打开槽位面板 → 点击第二颗宝石后立即交换并退出；不再增加确认框。
- 图标显示本回合可用/已使用；玩家回合开始重置。取消模式不消耗次数。
- 再次点击遗物按钮、点击空白处或切换其他指令会取消来源选择；锁定槽、空槽、赝品和过载回响不能成为目标。
- 验证重点：不同颜色槽、跨距离敌我交换、锁定槽、第二次点击前目标失效、取消不消耗、宝石归属不变量与按钮状态。

### 6.【护膝】— 中等

- 使用共用移动记账，在一次完整机动结束时检查玩家最终位置。
- 玩家必须实际消耗至少 1 点移动力，且最终与任意存活敌人正交相邻，才获得 3 点护盾；相邻多个敌人仍只触发一次。
- 与【游标卡尺】共存时，第一段不立即检查；第二段完成或玩家直接结束回合时，在最终位置检查一次。
- 强制位移、传送和敌方推动不进入自愿移动事件。
- 验证重点：斜角不触发、多敌人只一次、分段移动、第一段后直接结束、移动途中死亡。

### 7.【退场哨】— 中等

- 玩家拔出或嵌入前，记录所有存活敌人的意图语义快照；操作和意图刷新完成后再次记录并比较。
- 快照比较意图类型、目标、路径、影响格、伤害与预览效果，不比较本地化文本。
- 每回合第一次出现实质变化时，授予 1 点仅本回合有效的临时移动力；无关宝石搬运不触发。
- 将现有【旧式压力阀】的临时移动标记整理为按来源记录的临时移动池，避免两个遗物互相覆盖。
- 验证重点：意图不变、只改数字、只改路径、同回合多次变化、与压力阀并存、回合结束清空。

### 8.【拾荒钩】— 复杂

> 实现状态：已完成。

- `unit_die` 已发生在敌人宝石落地之后；遗物从该死亡单位本次掉落中按固定种子随机选一颗。
- 过载残响在死亡槽位效果结算后、正式掉落前消散，因此不会进入钩挂候选或战后奖励。
- 新增独立的“钩挂”宝石位置，扩展宝石位置不变量和转移接口；钩挂宝石不占普通手持位。
- HUD 同时显示普通手持宝石和钩挂宝石。钩挂宝石拥有一条专属嵌入指令，沿用普通嵌入的距离、锁定、颜色与过载校验。
- 专属嵌入成功后清空钩挂位。它不消耗或替代普通手持宝石的嵌入，因此玩家可以自行决定两颗宝石的处理顺序。
- 到期未使用时，通过统一宝石转移接口回到记录的原掉落格；若战斗先结束，也先归还地面再进入掉落宝石结算。
- 棋盘复用手持宝石的飞行与环绕表现：钩中的宝石从死亡格飞向玩家，并以反向、外圈轨迹持续环绕；HUD 在钩挂期间显示独立“钩入”指令。
- 验证重点：普通手持位已占用、一次死亡掉多颗、连锁死亡、敌方阶段触发、到期归还、最后一名敌人死亡。

### 9.【斗兽票】— 复杂，涉及 AI

> 实现状态：已完成。

- 在统一伤害边界发送带 `source_uid` 的完整伤害事件；只有实际生命伤害大于 0，且来源与受害者是两名不同的存活敌人时触发。
- 每场第一次满足条件后，在受害者身上记录报复来源；完整伤害结算事件发出后立即刷新该单位意图，避免伤害事务中途重入 AI。
- 为敌人行为增加“优先目标”入口：默认行为使用通用 AI 针对指定敌人生成移动加主动攻击意图；特殊行为可覆盖该入口，但仍必须使用自身当前宝石、状态、射程和移动力。
- 优先目标入口改为显式能力边界：已适配的滚轮犀牛和畸变蛆母保留各自的滚冲与繁殖循环；老法师等未安全适配的脚本化行为不会被通用 AI 覆盖，也不会消耗本场触发。
- 生成的报复意图写入明确元数据。该主动攻击实际结算后清除标记；若来源死亡或不再是合法目标，则清除标记并恢复普通意图。
- 不凭空增加攻击方式或额外行动。环境伤害、玩家伤害、自伤和只有护盾吸收的伤害不触发。
- UI：受害者状态区显示报复目标，意图线和预览直接指向该敌人。
- 已覆盖：普通伤害与带敌方来源的真实伤害、护盾吸收、玩家/自伤/环境来源、来源死亡、不可攻击回合、特殊敌人入口、单次主动攻击消耗、报复后恢复普通 AI、事件结构与战斗不变量。

### 10.【飞轮】— 中等偏复杂

- 玩家回合结束时读取共用移动记账的未消耗值并增加飞轮层数；层数存在战斗内遗物状态中，跨回合保留、战斗结束清空。
- 过载 AI 接管的自动移动只记录实际消耗，不触发【护膝】的自愿移动结算；该消耗会从【飞轮】可存储的剩余移动力中扣除。
- 玩家手动普通射击开始时，把当前层数与 `每层 +2` 快照进本次攻击上下文，使本次射击及其宝石结算使用同一个提高后的攻击基础伤害。
- 只有本次普通射击至少一次直接命中单位后才清空层数；全部落空则保留。护盾吸收仍属于命中。
- 红槽主动触发、反击、敌方攻击和纯环境伤害不读取飞轮。
- 多段射击共享同一次攻击快照，整次攻击结束后只清空一次。
- UI：遗物图标角标显示层数，详情显示“下一次普通射击 +X”；回合结束增加层数和命中清空均播放简短状态反馈。
- 验证重点：未移动/部分移动/分段移动、临时移动力、全部落空、护盾命中、多段射击、宝石连锁、战斗结束清空。

## 实施与交付节奏

每件遗物按以下顺序单独完成：

1. 同步权威设计口径与遗物数值引用；
2. 添加遗物定义和最小规则入口；
3. 添加该遗物需要的 UI 状态；
4. 用固定种子的聚焦测试覆盖触发、无触发和边界场景；
5. 检查战斗不变量、事件结构与设计同步；
6. 交付该件结果，再开始下一件。

【赝品】【保险丝】【调包】【拾荒钩】【斗兽票】属于高风险项，除聚焦测试外需要各自增加一条手动可视化探针；其他遗物以规则测试和现有 HUD 检查为主。

## 当前唯一待确认项

第 2 件【探针】仍是未通过设计评审的旧机制。其余九件已有可直接实施的技术路径；开始第 2 件前，需要确认沿用旧效果还是先替换设计。
