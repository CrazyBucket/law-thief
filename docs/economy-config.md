# 经济配置

局内金币奖励与商店价格集中在 `resources/adventure/economy_config.json`，调整数值不需要改脚本。

## 基准模型

当前基准把 `mu = 20` 定义为一个经济单位，初始金币为 `G_init = 85`。战斗奖励使用确定性正态抽样：

```text
金币 = round(mu × N(战斗_mu, 战斗_sigma))
```

抽样仍受 `combat_rewards` 的上下限保护，因此相同种子和房间会得到相同结果。事件使用同一单位：正向事件的期望收益为 `20 × 1 = +20`，负向事件的期望冲击为 `20 × -1.5 = -30`；两者的预算触发率分别为 0.4 和 0.2。`include_events` 为 `false` 时，事件只不计入预算预估，不会禁用地图上的事件。

`prices` 是以经济单位为基准的倍率，运行时先计算均值，再按 `price_sigma` 做种子确定的正态扰动：

```text
价格 = clamp(round(mu × price × N(1, price_sigma)), 均值 ± 2σ)
```

当前 `price_sigma = 0.15`，所以基础卡的均值为 35、实际价格约为 24–46；稀有遗物的均值为 240、实际价格约为 168–312。当前商店仍使用宝石货架，因此宝石沿用同一套档位价格。相同种子、房间和商品槽位会复现同一价格。

本基准按每关 15 个路径节点、每关 2 个商店、共 3 关配置。GDD 中“每关约 7 场战斗”仍作为路线体验目标，不强行把它写成地图生成器的硬编码比例。

## 战斗金币

`combat_rewards` 分为三档：

- `normal`：普通战斗（`NORMAL_COMBAT`）
- `elite`：精英战斗（`ELITE_COMBAT`）
- `boss`：Boss 战（`END`，同时兼容 `BOSS` / `BOSS_COMBAT`）

每档使用包含上下限的整数区间：

```json
"normal": {"min": 8, "max": 12}
```

同一局中，同一个房间的结果由局种子和房间 id 确定；重新进入或读档不会改变奖励。

## 商店价格

`shop_prices` 先按物品类型分组，再按稀有度配置整数区间：

```json
"gem": {
  "default": {"min": 12, "max": 18},
  "rare": {"min": 27, "max": 33}
}
```

当前基础类型为 `gem`、`relic`、`consumable`。每种类型必须保留 `default`，未单独配置的稀有度会回退到该区间。商店生成货架时只随机一次并把价格写入房间快照，所以读档、返回商店和购买结算都会使用同一价格。

消耗品目前只有定价能力；仓库尚未定义消耗品资源、背包和购买交付流程。补齐这些内容后可直接复用 `EconomyService.get_shop_price_range()` 与 `roll_shop_price()`。
